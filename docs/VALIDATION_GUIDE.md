# 验证指南

本指南说明每个 AI 工具需要验证哪些信息，以及如何填写验证报告。

---

## 一、安装与配置

### 需要搞清楚的问题

- **前置依赖**：这个工具需要什么运行时？（Node.js / Python / Go / Rust 等）需要什么版本？
- **安装方式**：有几种安装方式？推荐哪种？
  - 包管理器安装（npm / pip / brew / apt 等）
  - 二进制下载
  - 源码编译
- **安装过程**：
  - 安装过程中有没有报错？
  - 需要配置环境变量吗？
  - 需要配置 API Key 或 Token 吗？
- **验证安装**：如何确认安装成功？
  - `--version` 能输出正确版本号吗？
  - `--help` 能正常显示帮助吗？

### 记录要点

把每一条命令和它的输出都记录下来。遇到问题时，详细记录错误信息和解决办法。

---

## 二、基础使用流程

### 需要搞清楚的问题

- **最基本的使用方式**：这个工具最核心的功能是什么？怎么用？
- **命令结构**：
  - 子命令有哪些？
  - 常用参数有哪些？
  - 输入格式是什么？输出格式是什么？
- **典型场景**：
  - 日常开发中最可能用到这个工具的 2-3 个场景是什么？
  - 每个场景的完整操作流程是怎样的？

### 记录要点

- 每个典型场景都要有完整的命令 + 输出示例
- 输出如果很长，截关键部分即可，但要能说明问题

---

## 三、核心功能验证清单

这是**最重要的部分**——用事实说话，功能到底能不能用。

### 如何做

1. 先去官方文档/仓库 README，列出这个工具**所有宣称的功能点**
2. 逐一实测，标记状态：
   - ✅ 可用：功能正常工作
   - ❌ 不可用：功能报错或完全不工作
   - ⚠️ 部分可用：功能有缺陷或限制

### 记录格式

| 功能 | 状态 | 说明 |
|------|------|------|
| 功能描述 1 | ✅ / ❌ / ⚠️ | 实测情况、遇到的问题等 |

---

## 四、优点

尽量客观地列出这个工具的亮点：

- **易用性**：界面/命令设计是否直观？学习成本高不高？
- **功能深度**：有没有什么功能是其他同类工具没有的？
- **性能**：速度快不快？资源占用高不高？
- **生态/社区**：Star 数多少？维护活跃吗？文档全不全？
- **集成能力**：能不能方便地和其他工具/工作流集成？

---

## 五、缺点 / 问题

诚实列出不好的地方：

- **Bug**：有没有遇到崩溃、数据错误等问题？
- **体验问题**：哪里用着别扭？输出不清楚？参数设计不合理？
- **缺失功能**：有什么应该有的功能没有？
- **性能问题**：哪里太慢？内存泄漏？
- **文档问题**：哪里文档缺失或不清楚？

---

## 六、注意事项

列出"新手很容易踩的坑"：

- 配置上有没有什么特殊要求？
- 有没有和其他工具的冲突？
- 有没有什么容易被忽略的前提条件？
- 平台兼容性问题？（Windows / macOS / Linux）
- 有没有什么"看起来能用但实际上有坑"的功能？

---

## 七、总体评价（多维度评分）

对每个维度打 1-5 分（1 分最差，5 分最好）：

| 维度 | 含义 |
|------|------|
| **安装易用性** | 好不好装？步骤多不多？有没有坑？ |
| **文档质量** | 文档全不全？清不清楚？有没有示例？ |
| **功能完整性** | 宣传的功能都实现了吗？够用吗？ |
| **稳定性** | 会不会崩？结果可靠吗？ |
| **性能** | 响应速度、资源占用 |
| **综合推荐度** | 总体上是否推荐使用？值不值得投入时间学习？ |

评分标准：
- 5 分：非常出色，明显优于同类
- 4 分：很好，达到预期
- 3 分：一般，中规中矩
- 2 分：较差，有明显问题
- 1 分：很差，基本不可用

## 验证工作流程

1. **准备阶段**：从 `main` 创建验证分支，初始化验证目录
2. **信息收集**：阅读官方文档，了解工具的功能和特性
3. **安装验证**：实际安装，记录安装过程中的问题
4. **功能测试**：逐一测试核心功能，填写功能清单
5. **总结评估**：填写优缺点、注意事项、总体评分
6. **提交归档**：将验证报告提交到对应分支
